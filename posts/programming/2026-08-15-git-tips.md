Git 功能庞杂，但日常真正高频的其实就那么十几个。下面按「场景」整理，复制即用。

## 改掉刚提交的失误

```bash
# 改最近一次提交的信息
git commit --amend -m "新的提交信息"

# 漏了文件？补进上一次提交（不新增 commit）
git add forgotten.py
git commit --amend --no-edit
```

## 救回误删 / 误改

```bash
# 查看几乎所有历史动作（含已 reset 的提交）
git reflog

# 恢复到某个丢失的提交
git checkout <commit-hash>
# 或基于它新建分支
git branch rescue <commit-hash>
```

## 保持历史整洁

```bash
# 把当前分支的 N 个提交变基到最新 main 上
git fetch origin
git rebase origin/main

# 交互式重写最近 3 个提交（合并 / 改写 / 重排）
git rebase -i HEAD~3
```

> 黄金法则：**不要对已经推送到共享分支的提交做 rebase / amend**，否则会扰乱他人历史。

## 暂存进行到一半的工作

```bash
git stash            # 把未提交改动藏起来
git stash pop        # 恢复最近一次 stash
git stash list       # 查看所有 stash
```

## 看清楚「到底改了啥」

```bash
git diff --stat                 # 改了哪些文件、各多少行
git log --oneline --graph -10   # 紧凑的分支图
git blame file.py -L 10,20      # 这几行是谁、何时写的
```

## 小结

| 场景 | 命令 |
| --- | --- |
| 修最近提交 | `git commit --amend` |
| 找回丢失提交 | `git reflog` |
| 整洁地同步主线 | `git rebase origin/main` |
| 临时藏改动 | `git stash` / `git stash pop` |

把这些变成肌肉记忆，版本控制就从「心惊胆战」变成「随手就好」。
